# 재양자화 버림에 의한 크기 손실 (2026-10-30, 가설)

## 증거

SqueezeNet 을 보드에서 돌리며 층마다 중간 텐서를 떠서, 보정 기록(calib.yaml)의
범위와 대조했다. 보정은 같은 이미지로 VTAInterpreter 에서 떴으므로, 보드가
같은 값을 내야 한다.

| 텐서 | 기대 q최대 | 실측 q최대 | 비율 |
|---|---|---|---|
| concat0 | 58.9 | 46 | 0.78 |
| concat1 | 89.8 | 82 | 0.91 |
| concat2 | 61.7 | 49 | 0.79 |
| concat3 | ~137 | 98 | ~0.72 |
| concat4 | 83.5 | 63 | 0.75 |
| concat5 | 95.9 | 61 | 0.64 |
| concat6 | 104.4 | 38 | **0.36** |
| concat7 | 32.7 | 9 | **0.28** |

특정 층이 깨진 것이 아니다. 전 층에 걸쳐 조금씩 작아지고 그것이 누적된다.
마지막 특징맵(relu23)은 int8 범위의 1/7 만 쓰고 96% 가 0 이다. 그 상태로
1000 클래스 분류를 하니 답이 엉뚱해진다.

덤프 43개 중 전부 0 이거나 포화된 층은 하나도 없었다. 연산이 깨진 것이
아니라 **크기가 새는** 것이다.

## 대조 실험 — ResNet-18 은 새지 않는다 (2026-10-31)

같은 방식으로 ResNet-18 의 층별 덤프를 떠서 보정 기록과 대조했다.

```
ResNet-18    1.41  1.41  1.10  0.72  1.09  0.86  1.21   <- 1 근처, 추세 없음
SqueezeNet   0.78  0.91  0.79  0.72  0.75  0.64  0.36  0.28   <- 단조 감소
```

(비율이 1 을 넘는 것은 스케일을 보정 최대값에서 역산한 근사 탓이다.
중요한 것은 **단조 추세의 유무**다.)

ResNet 은 끝까지 int8 범위를 잘 쓴다 — 최대값이 127, 105, 122, 88 로 유지된다.
SqueezeNet 만 쪼그라든다.

## 숫자가 맞는다

SqueezeNet 의 VTA 컨볼루션은 24개다. 층당 유지율을 r 이라 하면
`r^24 = 0.28` 에서 **r = 0.948**, 즉 층당 5.2% 손실이다.
그 층들의 전형적인 양자값이 10~20 이므로 **0.5 LSB 버림은 2.5~5%** 에
해당한다. 우연이라기엔 잘 맞는다.

## 가설 — 시프트가 버림이다

VTA 의 컨볼루션 재양자화는 누산기를 오른쪽으로 `shift` 비트 미는 것이다.
산술 우시프트는 버림이므로 매번 평균 0.5 LSB 씩 아래로 치우친다. 값이
작아질수록 상대 손실이 커져 가속한다. 위 표의 모양과 정확히 맞는다.

ResNet 이 버티는 이유도 설명된다. 채널이 64 이상이라 누산 항이 많아 상대
편향이 작고, 잔차 덧셈이 크기를 되살린다. SqueezeNet 의 squeeze 층은 출력이
16 채널이고 1x1 이라 누산 항이 적어 편향이 그대로 드러난다.

## 고치는 방법 — 바이어스에 반 LSB 를 더한다

하드웨어를 바꿀 필요가 없다. 버림 시프트를 반올림으로 만드는 고전적인 수법은
시프트 전에 `1 << (shift-1)` 을 더하는 것이고, 누산기에 더해지는 값은
**바이어스**다. 바이어스는 번들 생성 시점에 `VTASave` 가 내보낸다.

즉 각 컨볼루션의 int32 바이어스에 `1 << (shift-1)` 을 더해 두면, 하드웨어의
버림 시프트가 반올림처럼 동작한다. 컴파일러 쪽 한 줄짜리 변경이다.

주의할 점 둘. `shift` 가 0 이면 더하지 않는다. 그리고 바이어스가 없는
(`doBias=0`) 컨볼루션에는 적용할 수 없으므로, 그 경우 바이어스를 만들어
넣거나 건너뛴다.

ResNet 회귀가 나지 않는지 반드시 확인한다. 반올림은 평균적으로 더 정확하므로
깨질 이유는 없지만, 기준값(281/207/340 과 확신도 0.478113)이 바뀌는지는 본다.


## 구현 — `ci/patch_requant_round.py` (기본 꺼짐)

바이어스 버퍼를 제자리에서 고치고 `VTASynchronize` 뒤에 원복한다. 동기화
뒤이므로 DMA 와 겹치지 않고, 임시 버퍼를 만들지 않아 CMA 를 더 쓰지 않는다.

**`NESTC_REQUANT_ROUND` 가 설정되어 있을 때만 동작한다.** 패치를 적용해도
켜지 않으면 동작이 전혀 바뀌지 않는다. 검증되지 않은 런타임 변경으로 보드를
멈추는 일(2026-10-30 에 CMA 로 한 번 겪었다)을 피하려는 것이다. A/B 는
재빌드 없이 환경변수만으로 한다.

적용은 보드에서 한다. `vtalib` 재빌드가 필요하다.

```sh
python3 ci/patch_requant_round.py ~/nest-compiler-2024
cd ~/nest-compiler-2024/build_aarch64 && make -j1 VTABundle
# 켜고 돌리기
sudo -E env NESTC_REQUANT_ROUND=1 PATH=$PATH ./squeezenet <이미지>
```

첫 실행은 사람이 지켜보는 자리에서 한다. ResNet 기준값
(281/207/340, aarch64 확신도 0.478113)이 유지되는지 먼저 확인하고,
그다음 SqueezeNet 이 281/205/340 으로 바뀌는지 본다.
