# 자동 실행에서 뺀 모델

`models/*.conf` 만 model-test 가 집어 간다. 여기 있는 것은 돌지 않는다.
지우지 않는 이유는 나중에 되살릴 수 있기 때문이다.

## sq-cut-fire2.conf, sq-cut-fire5.conf

SqueezeNet 을 중간에서 잘라 인터프리터와 보드를 비교하려던 것이다.
두 가지 이유로 뺐다.

**비교 지표가 성립하지 않는다.** 잘린 모델의 출력은 1000개짜리 분류
벡터가 아니라 4차원 특징맵이다. 인터프리터는 `Label-K1: 0 (probability:
0.0000)` 을 내고 보드는 `Result:` 줄을 아예 안 찍는다. 양쪽 다 argmax 가
뜻이 없어서 비교할 수가 없다.

**그리고 돌 때마다 CMA 를 64MB 씩 태운다.** 2026-11-02 model-test #23 에서
모델별 앞뒤 `CmaFree` 를 재서 확인했다.

| 모델 | 실행 전 | 실행 후 | 누수 |
|---|---|---|---|
| resnet18 | 253084 | 252836 | 248 kB |
| sq-cut-fire2 | 253292 | 187756 | **65536 kB** |
| sq-cut-fire5 | 187796 | 121956 | **65840 kB** |
| squeezenet | 122216 | 122256 | 0 |

끝까지 도는 모델은 새지 않는다. 답이 틀리는 squeezenet 조차 0 이다.
**중간에 죽는 모델만 정확히 64MB 를 들고 간다.** 게다가 죽을 때 출력이
완전히 비어 있다 — 오류 메시지도 스택 트레이스도 없다.

이것이 그 전날 밤 squeezenet 이 `dat_queue.h:39 fpga_buff_ != nullptr`
로 죽은 진짜 원인이었다. 알파벳 순으로 이 둘이 먼저 돌면서 128MB 를
태우고, 마지막 차례인 squeezenet 이 남은 메모리로는 못 돌았던 것이다.
하마터면 정확도 문제가 나빠진 것으로 오해할 뻔했다.

## 되살리려면

출력 텐서의 체크섬이나 합을 양쪽에서 찍어 비교하는 방법이 생기면 그때
`models/` 로 옮긴다. 자르는 도구 자체(`ci/cut_onnx.py`)는 멀쩡하고
번들 생성까지는 다 된다. 막힌 것은 비교하는 쪽이다.
